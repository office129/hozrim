# חוזרים לבראשית

אפליקציית ליווי אישי (קואצ'ינג/טיפול רגשי אחד-על-אחד) בשני ממשקים:

1. **אפליקציית לקוח** (`/login`, `/app/*`) — הלקוח נכנס עם אימייל וסיסמה, ורואה את הפגישות המוקלטות, תרגולים, חומרי פתיחה, יומן אישי פרטי, ואזור אישי. תצוגת מובייל היא "מסך טלפון" (bottom nav), ובדסקטופ עובר לפריסת דסקטופ עם תפריט צד.
2. **פאנל ניהול** (`/admin/*`) — המאמן/ת מנהל/ת לקוחות, מעלה הקלטות/תרגולים/סיכומים, ומגדיר את ספריית התכנים (תבנית הפתיחה הכללית).

נבנה עם Next.js (App Router) + TypeScript + Tailwind CSS + Prisma/Postgres, אימות עוגיות (JWT), ואחסון קבצים אמיתי (וידאו/אודיו/PDF) — בדיסק מקומי לפיתוח, או ב-Vercel Blob בפריסה אמיתית.

## פריסה חינמית ל-Vercel (כדי לקבל קישור חי)

זה המסלול המומלץ אם רק רוצים לראות/לבדוק את האפליקציה באינטרנט, בלי להריץ שום דבר במחשב. כל השלבים הם קליקים בממשק של Vercel, לא כתיבת קוד.

1. **היכנסו ל-[vercel.com](https://vercel.com)** והתחברו עם חשבון ה-GitHub שלכם (`office129`).
2. **New Project** → בחרו את הריפו `office129/hozrim` → לחצו **Import**.
   - Vercel יציע לבנות אוטומטית. אם הפריסה הראשונה נכשלת (צפוי, כי עוד אין בסיס נתונים) — זה בסדר, נמשיך.
3. בפרויקט שנוצר, עברו ללשונית **Storage**:
   - הוסיפו **Postgres** (יש אפשרות חינמית).
   - הוסיפו **Blob** (גם היא בחינם בהתחלה) — זה המקום שבו יישמרו קבצי הווידאו/אודיו/PDF שמעלים.
   - חיבור כל אחד מהם לפרויקט מוסיף בעצמו משתני סביבה — לא צריך להקליד אותם.
4. עברו ל-**Settings → Environment Variables** ובדקו: אם אין משתנה בשם בדיוק `DATABASE_URL`, מצאו את המשתנה שנוצר עבור ה-Postgres (למשל `POSTGRES_URL` או דומה), העתיקו את הערך שלו, והוסיפו משתנה חדש בשם **בדיוק** `DATABASE_URL` עם אותו ערך.
5. באותו מקום הוסיפו עוד שני משתנים:
   - `JWT_SECRET` — כל מחרוזת אקראית וארוכה (אפשר להמציא, למשל להקליד 40 תווים אקראיים).
   - `ADMIN_EMAIL` ו-`ADMIN_PASSWORD` — האימייל והסיסמה שבהם תרצו להתחבר לפאנל הניהול.
6. חזרו ללשונית **Deployments** ולחצו **Redeploy** על הפריסה האחרונה.
7. אחרי שהפריסה מסתיימת בהצלחה (עיגול ירוק), Vercel נותן קישור (למשל `https://hozrim-xyz.vercel.app`):
   - `/login` — אפליקציית הלקוח.
   - `/admin/login` — פאנל הניהול, עם האימייל/סיסמה שהגדרתם ב-`ADMIN_EMAIL`/`ADMIN_PASSWORD`.

השדרוג מ-DB חינמי לתשלום, אם יגיע יום שבו יהיו הרבה לקוחות/קבצים, נעשה גם הוא דרך אותה לשונית Storage בלי לשנות קוד.

## הרצה מקומית (למפתחים)

```bash
npm install
cp .env.example .env      # ומלאו DATABASE_URL (Postgres) ו-JWT_SECRET אמיתיים
npx prisma migrate deploy # יוצר את הטבלאות בבסיס הנתונים
npm run db:seed           # יוצר חשבון ניהול ראשוני + ספריית תכנים בסיסית
npm run dev
```

פתחו את http://localhost:3000 (אפליקציית לקוח) ואת http://localhost:3000/admin/login (פאנל ניהול).

פרטי חשבון הניהול הראשוני מודפסים בסוף הרצת `npm run db:seed` — שמרו אותם במקום בטוח. אפשר לקבוע אימייל/סיסמה מראש עם `ADMIN_EMAIL` ו-`ADMIN_PASSWORD`.

צריך בסיס נתונים Postgres גם לפיתוח מקומי (למשל דרך Docker, או חשבון חינמי ב-[neon.tech](https://neon.tech)).

## משתני סביבה (`.env`)

- `DATABASE_URL` — מחרוזת חיבור ל-Postgres.
- `JWT_SECRET` — מפתח חתימת ההתחברות. חובה לשנות בפרודקשן.
- `BLOB_READ_WRITE_TOKEN` — טוקן של Vercel Blob לאחסון קבצים שהועלו. ללא הגדרה, קבצים נשמרים בדיסק המקומי תחת `UPLOAD_DIR` (מתאים רק לפיתוח מקומי — לא שורד פריסות serverless).
- `UPLOAD_DIR` — תיקיית האחסון המקומי (משמש רק כשאין `BLOB_READ_WRITE_TOKEN`).
- `SMTP_*` (אופציונלי) — הגדרות שרת מייל אמיתי לשליחת סיסמאות זמניות וקישורי איפוס סיסמה. ללא הגדרה, ההודעות רק נכתבות ליומן השרת (מתאים לפיתוח/הדגמה) — בפרודקשן יש להגדיר שירות מייל אמיתי.

## מבנה עיקרי

- `prisma/schema.prisma` — מודל הנתונים (Admin, Client, LessonSession, Exercise, LibraryItem, JournalEntry).
- `src/lib/auth.ts` — אימות עם עוגיות httpOnly נפרדות למאמן/ת וללקוח/ה.
- `src/lib/storage.ts` — שמירה/הגשה של קבצים מועלים (דיסק מקומי או Vercel Blob), כולל תמיכה ב-HTTP Range לניגון וידאו/אודיו.
- `src/app/api/**` — כל נקודות הקצה (admin + client).
- `src/app/admin/**`, `src/app/app/**` — שני הממשקים.

## הערות לפרודקשן

- **מייל**: כרגע סיסמאות זמניות וקישורי איפוס נכתבים ליומן השרת אם אין SMTP מוגדר. יש לחבר שירות מייל אמיתי (Resend/SendGrid/וכו') לפני שימוש עם לקוחות אמיתיים.
- **אבטחת קבצים**: כשמשתמשים ב-Vercel Blob, הקבצים ציבוריים (כל מי שיש לו את הקישור המדויק, שאינו ניתן לניחוש, יכול לצפות/להוריד) — זו רמת אבטחה סבירה לרוב השימושים, אך שונה מהמצב בדיסק מקומי שבו יש בדיקת הרשאה בשרת בכל בקשה.
